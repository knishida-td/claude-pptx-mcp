# PPTX資料作成ルール

このドキュメントはMCPツール使用時にClaudeが自動参照すべきルールをまとめたものです。

---

## 基本方針

- 「資料作って」等の資料作成依頼では、SlideKitデザインシステムに従いPPTXを生成する
- PPTX生成後は必ず画像化して全スライドのテキスト溢れ・切れをチェック。問題ゼロまでループ
- 同名PPTXを再度開く時はPowerPointで先に閉じてから開く
- PPTXファイルを上書きしない。変更のたびに新バージョンで出力（_v1.pptx → _v2.pptx → _v3.pptx）
- PPTX編集後は毎回自動で `open -g` で開く（言われる前に実行）

---

## デザインバランスルール

### マージン
- 外側マージン: 0.5"（全辺統一）
- 10"×5.625"スライドの場合、コンテンツ領域: x=0.5〜9.5, y=0.5〜5.125

### フォントサイズ階層（最大3サイズ/スライド）
- タイトル: 22-28pt
- 本文: 14-16pt
- キャプション: 9-11pt
- 比率: ゴールデンレシオ(×1.618)または1.5倍

### カラー比率（60-30-10）
- 背景: 60%（#F5F5F5）
- テキスト: 30%（#333333）
- アクセント: 10%（#EF4823）

### テキストボックス
- 幅はテキスト量に合わせる（広すぎると右に空白ができる）
- 日本語16ptで1行に収まる文字数 ≈ 約25-28文字
- ボックス内パディング: 背景色ありなら左右に1文字分

### ホワイトスペース
- スライド面積の30-50%がホワイトスペース
- コンテンツ密度: 6要素以下/スライド

### 整列
- 1スライドあたり垂直グリッド線は3本以内
- 全要素は共通の左端（x=0.5 or 0.7）に整列

### 要素間スペーシング
- グループ内: 0.15"
- グループ間: 0.3"
- セクション間: 0.6"
- 行内アイテム間のギャップ: アイテム幅の1/3〜1/2

## 垂直中央配置（例外なし）

作成する全てのスライドは、例外なくコンテンツを縦中央に配置する。

- **セクションスライド**（タイトルのみ）: PageNum以外の全要素をスライド全体（5143500 EMU）で縦中央
- **コンテンツスライド**（ヘッダー+本体+フッター）: ヘッダー（~690120）とKeyMsg/PageNum（~4297680）の間の利用可能領域で本体コンテンツを縦中央
- 計算式: `ideal_top = available_top + (available_height - content_height) / 2`
- スライド作成時に最初から正しい位置に配置する（後から修正ではなく）

---

## 画像ルール

1. **縦横比（アスペクト比）を絶対に変えない** — 元の縦横比を維持。ボックスに合わせて歪ませるのは厳禁
2. **解像度は可能な限り高いものを使う** — 低解像度の画像はダサくなる
3. **画像は「画像ありき」でレイアウトしたスライドに入れる** — テキストやデータ中心のスライドの余白に後付けで小さく入れるとダサくなる。画像を入れたいなら、レイアウト設計の時点で「画像あり」で組む

---

## テキスト長制限（溢れ防止・最重要）

サーバー側にフォント縮小・description非表示等のフォールバックがあるが、
フォールバックが発動すると見栄えが悪化する。**入力段階でテキストを短くするのが最善**。

### 全レイアウト共通の文字数上限

| 箇所 | 上限 | 超過時のサーバー側フォールバック |
|---|---|---|
| タイトルスライドのtitle | 全角20文字 | フォント32pt→22ptまで縮小 |
| スライドタイトル（ヘッダー） | 全角18文字 | 22ptで折り返し（見栄え悪化） |
| keyMessage | 全角24文字 | フォント18pt→12ptまで縮小 |
| KPI value | 全角6文字 | フォント36pt→18ptまで縮小 |
| three-column各項目 | 全角10文字 | bullet除去+フォント10ptまで縮小 |
| definition title | 全角30文字 | 折り返し+高さ自動拡大 |
| numbered-list項目数 | 4項目まで | 5項目以上でdescription非表示 |
| definition項目数 | 3項目推奨 | 4項目+長titleでdescription非表示 |

### 禁止文字

以下の装飾文字はAI臭い印象を与えるため使用禁止。サーバー側でも自動除去される。

- 罫線文字: 「---」「===」「***」
- ダッシュ: 「──」「━━」「——」
- 区切りが必要な場合は「 - 」（半角スペース+ハイフン+半角スペース）を使う

### テキストが長くなる場合の対処法

ドキュメントやデータを読み込んで資料を作る場合、テキストが長くなりがち。以下で対処する:

1. **KPI**: 数値を丸める（「1兆2,038億円」→「1.2兆円」）
2. **3カラム**: 修飾語・括弧補足を削る（「国内プレミアムライン（今治認証）」→「国内プレミアム」）
3. **definition/numbered-list**: 項目数を減らすか、descriptionを短くする
4. **タイトル**: 副題はsubtitleフィールドに分離する

---

## KeyMsg（キーメッセージ）の補足

SlideKitのKeyMsg（各スライド下部のオレンジ太字メッセージ）は**24全角文字以内**が理想。

- 超過時はサーバーがフォントを18pt→12ptまで自動縮小するが、見栄えが悪化する
- 長い場合は括弧や修飾語を削って短縮すること
- 「...」で省略されることは無い（フォント縮小で全文表示される）

---

## プロセスフローの上限

横並びプロセスフロー（circle番号 + title + description）は**3ステップが上限**。

4ステップ以上は「番号付き縦リスト」パターン（左にcircle番号、右にtitle+desc、間にsep線）に切り替える。横並び4つ以上は1ステップあたり約1.7インチしか使えず、説明テキストが崩壊する。

---

## 提案資料は20枚以上

提案書・改善提案は最低20枚以上で厚みを出す。10枚程度の薄い資料はクライアントに信頼されない。

### 構成テンプレート（計20-24枚）
- 導入: 2枚
- 理解・分析: 6-8枚
- 施策: 8-10枚
- 効果・実行: 4枚
- クロージング: 1枚

---

## スライドテンプレート設計原則

1. **崩れない設計**: 要素がスライド外にはみ出さないか必ず検証。枠線・ボックスに頼らず、区切り線＋余白で構成する
2. **ミニマルな美しさ**: 白いカードボックスや巨大な塗り図形は避ける。KPIスライド（数字+区切り線+ラベル）や体制図（バナー+グリッド）のようなミニマルアプローチ
3. **1スライド1キーメッセージ**: 各スライドに強調されたキーメッセージ（赤帯 or 太字 or 大きなフォント）を1つ入れる。データや図の「だから何？」を明示する

---

## 視線誘導の原則（gensparkっぽさを避ける）

「とりあえずカードで囲って並べる」はAI生成スライドの典型パターン。視覚的階層がフラットになり、どこを見ればいいか分からなくなる。

### 禁止: 全カード均一の枠線レイアウト

- 3つ4つの白カードを横並びに均等に並べる構成は禁止
- カード全部にプライマリ色の枠線を入れるのも禁止
- 「囲うこと」ではなく「強調すること」が目的

### 推奨: 4つの強調手法

1. **サイズコントラスト**: 主役要素を他の要素の2倍以上のサイズにする（hero-focusレイアウトを使う）
2. **色のコントラスト**: プライマリ色(`EF4823`)は1スライドに1〜2箇所だけ。残りはbody/sub色で抑える
3. **矢印で関係を示す**: カードを並べるだけでなく `→` `↓` で因果/プロセス/フローを明示する
4. **空白で囲う**: ボックスで囲うのではなく、周りに余白を取って主役を「浮かせる」

### 視線フローの設計

- 1スライドで「最初に目がいく要素」を1つに絞る（左上から右下へZ型に流れる前提）
- 数値が主役なら数値を最大に、結論が主役なら結論を最大に
- 主役以外は段階的に小さく（タイトル22pt > 主役32-72pt > 補助14pt > 注釈11pt の階層）

---

## 1スライド1センテンス原則

各スライドのメッセージは1文に集約する。「○○が××なので△△する」が1文なら、それを構造化して可視化する。

### 構造化の例（sentence-diagram レイアウト）

「LTVを8,200円から15,800円（×1.9倍）に引き上げる」という文を:

- **主語**: LTV（中央上部、大型）
- **Before**: 8,200円（左カード、グレー）
- **After**: 15,800円（右カード、プライマリ色）
- **倍率**: ×1.9（バッジ）
- **補足**: クロスセル導線+LINE活用で実現（下部）

…のように分解し、矢印で関係を示す。1文を箇条書きで横に並べるのではなく、構造として配置する。

### センテンス構造別の図解レイアウト選択

センテンスの型に応じて適切なレイアウトを選ぶこと。

| センテンス型 | 例 | 推奨レイアウト |
|---|---|---|
| Before→After（変化） | LTVを8,200円→15,800円に上げる | sentence-diagram |
| 因果連鎖（A→B→C） | 新規CPA上昇→粗利圧迫→再投資縮小 | causal-chain |
| 要素合成（A+B+C=D） | クロスセル+LINE+メールでLTV1.9倍 | composition |
| 分解（A=B+C+D） | LTV改善は3つの構成要素から成る | decomposition |
| 対比（A vs B） | 新規依存ではなくLTV重視へ | contrast-pair |
| 放射的関連（中心+周辺） | LTV改善というテーマに紐づく要素群 | concept-map |
| 主役+補助 | 粗利+2.1億円が主、その内訳が補助 | hero-focus |

文を1スライドに書く前に「この文の構造は上のどれか」を判断してからレイアウトを選ぶ。「だらだら箇条書き」を避ける最重要ルール。

## 数値は4点セット（最重要）

数値だけポンと置くのは禁止。読み手は「何の数値か」「単位は何か」が即座にわからない。

### 必須の4要素

| 要素 | 例 | 役割 |
|---|---|---|
| **ラベル** | LTV | 何の数値か |
| **値** | 8,200 | 数字本体 |
| **単位** | 円 | スケール |
| **補足** | 既存顧客／年間 | 条件・前提 |

### 実装

- **kpi レイアウト**: `metrics: [{ label, value, unit, sub }]` の4点を必ず指定
- **bigtext レイアウト**: `{ heading, unit, context, subtext }` で「9,800 億円 / 日本のEC市場規模 / 2024年実績」のように分離
- **sentence-diagram レイアウト**: before/after の value と unit を分離フィールドで指定

### 禁止例 → 推奨例

```
❌ value: "8,200円", label: "LTV"
✅ value: "8,200", unit: "円", label: "LTV", sub: "既存顧客／年間"

❌ heading: "9,800億円"
✅ heading: "9,800", unit: "億円", context: "日本のEC市場規模"
```

単位を value に含めると、数値部だけを大きく/単位を小さく表示できなくなる。必ず分離する。

---

## ビジュアル要素は画像・アイコン（絵文字禁止）

絵文字は使わない。代わりに以下を使う:

- **アイコン**: `react-icons` のSVGを `sharp` でPNG化して挿入（`scripts/diagram_helpers.py` 参照）
- **イラスト**: undraw / Storyset / Higgsfield などで生成して `content.images` で配置
- **実物写真**: ぱくたそ（日本人モデル）または商品公式サイトから取得

絵文字を使うとレンダリング差異・低品質感が出る。サーバー側でも入力チェックされる。

---

## PPTX破損防止チェックリスト

PPTX生成・編集時に以下を厳守すること。

1. **既存PPTXをベースにする** — 新規作成せず、動作確認済みのPPTXをunpackして使う
2. **presentation.xmlのスライドサイズを変更しない** — 元ファイルのcx/cy値をそのまま維持
3. **[Content_Types].xmlに重複エントリを作らない** — 追記ではなく、全体を正確に書き直す
4. **presentation.xml.relsのrIdは連番にする** — 既存のrId構造を壊さない
5. **presentation.xmlのsldIdLstとrelsのslide参照を一致させる** — スライド数が変わったら両方を同時に更新
6. **変更は最小限にする** — スライドXMLの中身だけを差し替え、構造ファイル（rels, Content_Types, presentation.xml）は必要な箇所のみ修正
7. **リパック前にバリデーションを実行する**:
   - `[Content_Types].xml` のスライド数が実ファイル数と一致するか
   - `presentation.xml.rels` のスライド参照が実ファイルと一致するか
   - `presentation.xml` のsldIdLst数がrelsと一致するか
   - 全slideN.xml.relsが存在するか
8. **勝手にスライドサイズ・フォーマットを変更しない** — 4:3か16:9かは元ファイルに従う
9. **不要ファイルをzipに含めない** — .bak、.tmp、.DS_Store等を除外
10. **全スライドXMLに`<p:bg>`セクションを含める** — 背景設定がないとPowerPointがエラーを出す
11. **`<p:sp>`内で`prstGeom="line"`を使わない** — PowerPointは線を`<p:cxnSp>`（コネクタ）として期待する。線が必要な場合は薄い矩形（`prstGeom="rect"` + `cy="12700"`等）で代替
12. **XML正規表現で`[^/]`を使わない** — OOXML属性値にはスラッシュが含まれる。代わりに`[^>]*`を使う
13. **プレースホルダー置換時にXMLエスケープする** — `&` → `&amp;`、`<` → `&lt;`、`>` → `&gt;`
